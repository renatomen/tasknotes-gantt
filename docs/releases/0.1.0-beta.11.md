# TaskNotes Gantt 0.1.0-beta.11

The largest release so far, and the first since July. Working-time calendars arrive as a complete feature: calendar notes, a visual editor, working patterns, availability and calendar sets. The chart also gains a legend, independent bar treatment channels, and TaskNotes calendar items in the timeline. And an important fix: task dates no longer shift by a day in timezones behind UTC.

Each entry below is a summary, and its link leads to the full documentation. To try calendars end to end, follow [Add working time: a worked example](https://tngantt.com/getting-started/#add-working-time-a-worked-example).

## Added

- **Calendars and working time.** (#267, #268, #269, #270, #271, #272, #273, #275, #276, #277, #278, #279, #281)
  - A calendar is an ordinary note in your vault that says which days work happens on. With one in place, the chart can shade the days nobody works and, if you opt in, count working days for an end it works out for you and split bars around days off. All of it is counted in whole days: a calendar can record working hours, but nothing schedules by them yet. [Calendars and working time](https://tngantt.com/features/calendars/)
  - A task whose Calendar Property link does not resolve schedules as though it had no calendar. [Working days: which dates move](https://tngantt.com/features/calendars/#working-days-which-dates-move)
  - **Calendar sets** combine several calendar notes into one, so a task can follow all of them through a single link, and the chart can mark the days on which the calendars it shows disagree. The **Select calendars…** command chooses which calendars a view shades. [Calendar sets](https://tngantt.com/features/calendar-sets/)
  - Working patterns are written as standard iCalendar recurrence rules (RFC 5545 `RRULE` values). A calendar note is still plugin frontmatter: there is no `.ics` import or export. [Recurrence rules, and what they are not](https://tngantt.com/features/calendars/#recurrence-rules-and-what-they-are-not)
- **A visual editor for calendar notes.** (#286, #287, #288, #289, #290, #291, #292, #293, #294, #295, #296, #297, #298, #300, #301, #303, #304, #305, #306, #307)
  - Edit a calendar note as a form, with a builder for the working pattern, a timezone picker, a colour picker, and previews of the result before you save. **Create calendar** and **Create calendar set** start a new note. [The calendar editor](https://tngantt.com/features/calendar-editor/)
  - The editor rewrites each key you change as a whole. Before editing a note you wrote by hand, read [Saving and closing](https://tngantt.com/features/calendar-editor/#saving-and-closing): a comment inside a changed key is lost, and the editor expects the frontmatter written plainly.
- **Availability blocks: extra working time beyond the main pattern.** (#308, #321)
  - A calendar can add working days to its pattern, such as an on-call Saturday, as availability blocks. Days off belong in its `non_working` list instead. The editor does not edit blocks yet. [Availability blocks](https://tngantt.com/features/calendar-editor/#availability-blocks)
- **TaskNotes calendar items in the timeline.** (#386)
  - The chart can show what the TaskNotes calendar shows, as read-only bars: recurring task instances, time entries, timeblocks, property-based events and external calendars. Each family is opt-in, with one exception the page describes. [Calendar items](https://tngantt.com/features/calendar-items/)
  - External calendars are read through TaskNotes' own subscriptions. The Gantt adds no feed, credential or fetch of its own, though showing an ICS feed can make TaskNotes fetch it.
- **A legend that explains the chart.** (#391, #406)
  - The legend lists the cues the chart can draw, with samples that follow the view you are looking at. It opens at the right or the bottom, and **Default legend position** sets where it opens. [The legend](https://tngantt.com/features/legend/)
- **Hovering a dependency arrow describes the dependency.** (#404)
  - Point at the connector itself and the tooltip names the relationship it represents, rather than leaving you to trace the arrow between two rows.
- **Independent Bar fill, Bar strip and Task icon.** (#312)
  - **Bar fill** and **Bar strip** are now separate settings, so a bar can be filled by one thing and striped by another, for example filled by status and striped by priority. **Task icon** was already independent and stays so. [Bar fill, Bar strip and Task icon](https://tngantt.com/features/legend/#bar-fill-bar-strip-and-task-icon)
- **Estimate meaning and Non-working-day rendering are separate settings.** (#315, #319, #320)
  - **Estimate meaning** chooses whether an end the plugin works out counts the working days of the task's own calendar or plain calendar days, and a single task can override it. **Non-working-day rendering** decides whether days off are only shaded or can also split a bar into segments. [Estimate meaning](https://tngantt.com/settings/timeline/#estimate-meaning)
- **A prompt when you drag an end the plugin worked out.** (#314, #336, #347, #348)
  - Resizing a bar's worked-out end can ask whether you meant to grow the estimate or also pin a date there, and a **Don't ask again** toggle saves your answer as the view's **Inferred date drag** setting. The question only arises when **Time Estimate Update** has somewhere to write. [Inferred date drag](https://tngantt.com/settings/timeline/#inferred-date-drag)
- **A torn edge marks a date the task does not actually have.** (#395, #397, #398, #406)
  - With **Show date-status indicators on bars** on, the default, a bar end whose date was never written down is cut with a zigzag edge instead of a flat one. A bar too narrow to carry the teeth can hide it. [Date-status indicators](https://tngantt.com/features/appearance/#date-status-indicators)

## Changed

- **Leaving the status, priority or date mappings blank now means "use the TaskNotes default", not "no property".** (#254)
  - A blank *Status Property* previously switched off everything that depended on status: colouring bars by status did nothing, the status icon did nothing, and double-clicking a status cell opened the note instead of the picker. (This assumes TaskNotes reports its field configuration; if it cannot, mappings stay blank and the view goes read-only.) Blank mappings now resolve to the properties TaskNotes is configured with, for status and priority as well as dates, and inline editors resolve against the same values.

## Removed

- **The red border on tasks with swapped dates.** (#412)
  - A task whose start falls after its due date no longer draws a red outline. The orange fill still marks it. A fuller treatment — a badge beside the bar naming what is wrong — is planned; until it ships, a swapped task shown with split rendering carries no visible cue.

## Fixed

- **Tasks no longer shift by a day when you edit their dates.** (#311, #489, #490)
  - Dates written as plain calendar days were read as UTC instants, so in any timezone behind UTC a task saved as September 21–23 drew on September 20–22 — and dragging it then saved the wrong day, compounding with every correction. Calendar dates are now read as calendar dates.
  - Three further defects found while verifying that fix are also closed: a moved three-day bar could briefly display as two days, closely spaced corrective moves could roll back after a refresh, and resizing a task that appears in more than one place could leave the other copy behind.
  - One symptom from the original report — an intermittent change in bar width during a drag — was not reproduced, so #311 stays open for it. Please keep the reports coming if you still see it.
  - Thanks to @donaldwdci for reporting this and for the detailed follow-up that made the remaining causes findable.
- **Tooltips never appeared on touch-capable hardware, and dependency tooltips were empty everywhere.** (#404)
  - Any device reporting a touch point — including most laptops with a touchscreen — suppressed every tooltip in the chart. Tooltips now appear on anything that can hover, a touchscreen laptop included; a touch-only device still has none, since a tooltip is a hover affordance.
  - Separately, and on every device: the chart hands tooltip content a wrapper around whatever was hovered, and the plugin read it as though it were the task, so dependency tooltips rendered as an empty box. They now carry their content.
- **Two Gantt views in one workspace no longer interfere with each other.** (#316)
  - Injected styles were shared across views, so opening a second chart could restyle the first. Each chart now owns its own.
- **Rows now appear and disappear when their dates change, instead of at the next reopen.** (#472, #473)
  - With *Show date-status indicators on bars* off, filling in a date a task was missing left *Show tasks with no dates* and *Show tasks with only one date* filtering that row on the classification it used to have — so a task you had just given real dates could stay hidden, and the toolbar could read "6 results" over a four-row chart, until you reopened the view.
  - *Hide top-level subtasks* removes the duplicate top-level copy of a task that also appears as someone's subtask. A task that became a subtask during a refresh kept that duplicate on screen anyway.
- **Icons on one-cell bars are aligned.** (#393)
- **A live Bar fill change no longer garbles split rendering.** (#318)
- **The legend's swatches match the chart.** (#402, #407, #410)
  - The torn-edge swatch now shows the same cut the chart draws, shading swatches have cells to contrast against, and the legend no longer describes a treatment that was retired.
- **Calendar editing and validation.** (#299, #302, #323, #324, #326, #327, #328, #329, #330, #331, #333, #334, #335, #337, #338)
  - Impossible dates are rejected, as are recurrence rules a day-granularity calendar cannot evaluate safely — malformed ones, and ones whose occurrences would drift with whichever window you happen to be looking at — before either can freeze or mis-render the preview. An ordinary open-ended rule, such as a plain Mon–Fri weekly pattern, is still accepted as always.
  - A colour is sanitised before it reaches an inline style; Discard is disabled while a save is in flight; a newly created calendar note routes to the editor even when the vault indexes it late; deleting a calendar note re-resolves the chart; folder-qualified calendar links resolve; and the conflict banner attributes each conflict to the calendar it came from.
